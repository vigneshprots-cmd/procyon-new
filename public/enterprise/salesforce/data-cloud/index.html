Our view

Data Cloud programs fail on identity rules, not ingestion.

Getting data into Data Cloud is the easier half. Data streams and templates bring CRM, web and ERP data in quickly. The hard half is deciding when two records are the same person or the same account, which system wins when they disagree, and what each profile may be used for.

Those are business decisions dressed as technical ones. Left to the build team, match rules end up too loose, merging two customers into one profile that an agent will then describe to the wrong person, or too strict, so the duplicates survive and nothing changes.

  • Unifying everything at once

    Every source connected on day one, before anyone has said what the profile is for. Months pass before a single team uses it.First move: one use case, and only the sources it needs

  • Match rules nobody signed

    Exact email match misses anyone with two addresses. Loose name and address matching merges people who are not the same.First move: match and reconciliation rules approved by data owners, with match rates reported

  • Consent as an afterthought

    Someone opts out in one system and keeps receiving email from another, because consent was never carried with the record.First move: consent and purpose captured per source before activation

  • Copying the warehouse

    Finance figures copied into CRM become a second version that drifts within weeks, and AI scores disagree with the board pack.First move: zero-copy where the warehouse is the system of record

Nothing is activated until identity and consent are signed.

The order matters more than the speed. Each step ends with a decision the data owners sign, so the first activated profile is one the business already agrees with.

Data quality

AI acts on the record, so the record gets fixed first.

Four problems every Data Cloud program clears before agents or journeys are allowed to act on the data.

Check data quality →
  • Duplicate customersThree accounts for one customer, each with a different owner. Resolved into one profile, with match rates reported to the data owner.
  • Conflicting fieldsERP and CRM disagree on the billing address. A golden-record rule decides which system wins, field by field.
  • Untraceable valuesNobody can say where a number came from. Every field carries its source system and last change.
  • Consent gapsMarketing emails people who opted out elsewhere. GDPR, CCPA and HIPAA consent is applied before any activation.

Asked before connecting a single system.

What does a Salesforce Data Cloud implementation involve?

Connecting data sources, mapping them to the Data Cloud model, setting identity resolution rules to build unified profiles, applying consent and governance, then activating those profiles in Sales, Service, Marketing Cloud and Agentforce.

Is MuleSoft needed to integrate Salesforce with an ERP?

Not always. MuleSoft suits many systems and reusable APIs. Simpler flows can use native Salesforce APIs or platform events. Procyon recommends the connection pattern per integration in the design phase.

Which systems can Procyon integrate with Salesforce?

Commonly SAP, Oracle, NetSuite, Workday, Snowflake, Databricks, Tableau, Slack, WhatsApp and Okta, plus custom and legacy systems through MuleSoft or APIs.

Can Data Cloud work with Snowflake without copying data?

Yes. Zero-copy federation lets Data Cloud read from Snowflake or Databricks in place, which avoids duplicate pipelines and keeps one source of truth.

How are GDPR, CCPA and HIPAA handled?

Consent, retention and access rules are designed into the data model and enforced before any profile is activated. Healthcare programs add HIPAA controls and Salesforce Shield encryption where required.
