Our view

The assistant is only as good as the documents it may read.

Most of the work in a knowledge assistant is not the model. It is deciding which documents count as the answer, making sure each person only retrieves what they are cleared to see, and keeping the index as current as the policy it reflects.

Teams that skip those decisions get an assistant that quotes last year's leave policy to the wrong country, or surfaces a restricted file to a contractor. Trust goes in a week, and it does not come back with a better prompt.

  • No agreed source of truth

    Three versions of the same policy sit in SharePoint, Confluence and an email attachment. The assistant picks one, and nobody can say whether it picked the right one.First move: name an owner and an approved location for each subject

  • Permissions flattened in the index

    Documents are copied into one search index under a service account, and the access rules stay behind in the source system.First move: retrieval that checks the asking user's access, every time

  • An index that lags the business

    Policy changes on Monday, the assistant learns about it a month later. Freshness is a design decision, not a maintenance task.First move: re-index each source when its documents change

  • Quality judged by anecdote

    One bad answer in a leadership demo outweighs a thousand good ones, because nobody measured the thousand.First move: a test set of real questions with approved answers, run before every release

Why assistants get switched off

Untrusted answers end more pilots than cost does.

Four failures that show up in the first month, and the control in place for each before launch.

  • Made-up answers.The model fills gaps from its general memory and sounds confident doing it. Control: answers come only from retrieved, approved passages, and when nothing relevant is found the assistant says so and offers a person.
  • Leaked documents.A shared index lets a contractor surface salary bands or a board paper by asking the right question. Control: each query is filtered by the asking user's access in the source system.
  • Stale answers.The policy changed weeks ago and the assistant still quotes the old one. Control: sources re-indexed when documents change, with an owner per source and the version shown in the citation.
  • No accountability.A wrong answer is reported and nobody can reconstruct what the assistant read. Control: every question, retrieved source, answer and handover logged, so any answer can be replayed.

Asked before building a knowledge assistant.

What is a RAG knowledge assistant?

A retrieval-augmented generation assistant searches approved company documents for the passages relevant to a question, then has a language model answer from only those passages, with the source cited. It answers from company knowledge rather than from the model's general memory.

How do knowledge assistants avoid hallucinations?

Answers are generated only from retrieved, approved documents, every answer cites its source, guardrails filter unsafe output, and questions below a confidence threshold are handed to a person.

Which document sources can be connected?

Commonly SharePoint, Salesforce Knowledge, ServiceNow knowledge bases, Confluence and PDF libraries. The Enterprise RAG Starter includes connectors for Salesforce Knowledge, SharePoint and PDFs.

Can the assistant respect document permissions?

Yes. Retrieval is permission-aware and mirrors existing access rights, so each user only gets answers from documents they are already allowed to see.

How long does a knowledge assistant take to build?

Starting from the Enterprise RAG Starter, production generative AI use cases typically reach first value in about 8 weeks, depending on the number of sources and the review needed.
