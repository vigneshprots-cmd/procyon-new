Our view

Agent pilots stall on scope and data, not on the model.

The agent pilots that stall usually share a shape: a broad agent asked to help customers with anything, pointed at a knowledge base nobody has reviewed in years, and tested with a handful of friendly questions. It demos well and fails on the first awkward conversation.

An Agentforce agent is a set of topics, the actions each topic is allowed to take, and the instructions and guardrails around them. Getting those right for one narrow job is most of the work, and it is the part that carries over to the second and third agent.

  • Topics drawn too wide

    One topic that covers billing, orders and complaints classifies requests badly, and the agent picks the wrong action with full confidence.First move: one topic per job, with a written out-of-scope list

  • Grounding data nobody owns

    Duplicate accounts, stale knowledge articles and records with no owner. The agent repeats whatever it reads, to the customer.First move: score the records and articles the agent will read

  • Actions without limits

    An agent that can update a record, issue a credit or book a visit needs the same limits a new employee would have.First move: read-only actions first, write actions behind confirmation

  • No test set

    Without a fixed set of real past conversations, every prompt change is a guess and nobody can say whether the agent got better.First move: a test set built from real cases, run before every release

Each is a starting configuration in the Agent Launch Kit, with its guardrail already defined. The first six can be in production in under four weeks. The last row reads data across several clouds or acts on money and schedules, so it comes second.

Case triage agent
Reads each new case, sets category and priority, and routes it to the right queue with a summary. Low-confidence cases go to a human queue untouched.
Tier-1 self-service agent
Order status, account and how-to questions on web, WhatsApp or the customer portal. Answers only from approved knowledge, with one-click handover.
Agent assist and reply drafter
Drafts replies from knowledge and past cases so service agents resolve in fewer touches. Every draft cites its source and is sent by a person.
Inbound lead qualifier
Answers web and email enquiries, asks qualifying questions and books meetings for the right rep. Hands over on pricing or contract questions.
Internal knowledge assistant
Policy, product and process answers for employees in Slack, from SharePoint and PDF libraries. Respects document permissions.
Deal health coach
Flags stalled opportunities, missing stakeholders and slipping close dates before the forecast call. Suggests only; reps decide what changes.
Renewal and churn watcher
Phase 2. Spots usage drops and support spikes across Data Cloud, Service and Revenue Cloud, then drafts a save plan. Never contacts customers directly.
Order and quote desk agent
Phase 2. Checks quotes against pricing rules, chases missing approvals and flags errors before the customer sees them. Approvals stay with the deal desk.
Field dispatch agent
Phase 2. Matches jobs to technicians by skill, location and parts, and reschedules when plans change. Dispatchers confirm any same-day change.

Not recommended as a first agent: anything that commits money, changes contract terms or contacts customers unprompted. Those wait until the first agent has a track record.

How it runs

Four sprints, one agent in production.

The Agent Launch Kit runs one week per sprint. The success metric is fixed in week one, so launch is judged against a number rather than a demo.

  1. Week 1Pick and ground

    One high-volume use case, the records and knowledge it may read, and how success is measured. Stale articles are retired before the agent sees them.

    Use case, sources and metric signed
  2. Week 2Build and instruct

    Topics, actions and instructions configured from the kit in a sandbox. Actions scoped to what the job needs and nothing more.

    Agent working in sandbox
  3. Week 3Test and guard

    The test set of real past conversations, red-team prompts, accuracy checks and the handover rules, reviewed with the risk owner.

    Test results and guardrails approved
  4. Week 4Launch and measure

    Live with real users, conversations reviewed daily against the metric, and failures fed back into the test set.

    Agent in production

Testing and guardrails

Five ways agents fail in production, tested before release.

Every agent ships on the Einstein Trust Layer, answers from approved sources, hands over below a confidence threshold and logs every conversation. These are the checks behind those controls, documented for security, legal and compliance review.

RoutingThe wrong topic picks it up

A refund question lands in order status, and the agent answers a question nobody asked.

Labelled topic test setEvery test utterance carries the topic it should reach. Classification is re-run after each instruction change, before release.

GroundingA confident answer from an old article

The agent quotes a policy that changed last year, because the article was never retired.

Approved, retrieved sources onlyAnswers come from Salesforce records and reviewed knowledge through retrieval, not from the model's memory, and stale articles are removed before launch.

ActionsThe wrong record is changed

An update lands on a duplicate account, or an action runs twice in one conversation.

Scoped and confirmed actionsActions see only the records the running user may see. Anything that writes data asks for confirmation or goes to a person.

AdversarialTalked out of its instructions

A user coaxes the agent off topic, or asks for another customer's details.

The agent keeps rephrasing an answer that does not help, and the customer gives up.

How long does an Agentforce implementation take?

With Procyon's Agent Launch Kit, the first Agentforce agent reaches production in under four weeks: one week to pick and ground the use case, one to build, one to test and guard, and one to launch and measure.

Which Agentforce use cases should we start with?

Start where volume is high and answers already exist: case triage, tier-1 self-service, inbound lead qualification or an internal knowledge assistant. These prove value fast and build trust for agents that take more complex actions.

Do we need Data Cloud for Agentforce?

Not for every agent. Agents can be grounded in Salesforce records and knowledge articles. Data Cloud becomes important when an agent needs a unified view of customers across ERP, web, commerce and service systems.

How do you stop AI agents from giving wrong answers?

Each agent answers only from approved, retrieved sources, runs through the Einstein Trust Layer, hands over to a person below a confidence threshold and logs every conversation for review. We red-team prompts before launch.

What results can we expect from Agentforce?

In our healthcare rollout, AI agents resolved 60% of tier-1 patient queries, service response was 50% faster and administrative workload fell by 35%. Each engagement sets its own success metric in week one.

Can Agentforce use models other than Salesforce's?

Yes. Agentforce can work with models from providers such as OpenAI, Anthropic and Google Vertex AI through Salesforce's model gateway, with the same trust controls applied.
